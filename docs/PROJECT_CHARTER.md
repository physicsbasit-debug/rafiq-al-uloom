# رفيق العلوم — ميثاق المشروع

## الرؤية

رفيق العلوم منظومة تعلم تفاعلية موجهة للطالب، وليست بنك ملخصات أو صفحة أسئلة فقط.

يبني كل درس وفق التسلسل:

هدف التعلم → شرح مبسط → مثال → نشاط → سؤال → تغذية راجعة → قياس إتقان

## الفئة المستهدفة

طلبة مواد العلوم والفيزياء والكيمياء والأحياء.

نطاق MVP الحالي:

- الصف: العاشر
- المادة: الفيزياء
- الوحدة: الموجات
- عدد الدروس: 4 دروس

## الاسم المرحلي

رفيق العلوم

## الحالة الحالية عند مرشح تجميد v0.5

- تجربة الطالب الأساسية مكتملة للمسار الحالي.
- طبقة بيانات المحتوى غير المتزامنة مجمّدة عند `v0.3-data-layer-complete`.
- Schema وRLS وSeed المحلية على Supabase قابلة لإعادة البناء، والمزوّدان المحلي والسحابي متكافئان ضمن عقد `ContentRepository`.
- Auth وProfiles وAuthorization Guards وRLS مكتملة ومجمّدة عند `v0.4-auth-security-complete`.
- حفظ نتائج الإتقان المرتبطة بالمستخدم مكتمل عبر Service + Repository + RPC + PostgreSQL مع idempotency وretry ومصالحة النتيجة الرسمية.
- المسار الحقيقي من Auth حتى React Hook وRPC والصفوف المخزنة مثبت باختبار Composition.
- تكافؤ حساب الدرجة بين TypeScript وPostgreSQL مثبت ببوابة Parity مستقلة، بما فيها Unicode و`already_saved`.
- آخر دليل إغلاق تشغيلي قبل D5-C2 هو `npm run verify:mastery-results-closure` الناجح عند `f042ca9`: 508 اختبارًا أساسيًا + 89 اختبار Supabase = 597 اختبارًا فريدًا.
- D5-C2 هي دفعة التوثيق والتجميد الأخيرة قبل إنشاء `v0.5-mastery-results-cloud-complete`.

## القواعد التأسيسية

1. لا كود قبل وضوح البنية.
2. لا ملف ضخم يجمع واجهة ومنطقًا وبيانات بلا حدود واضحة.
3. فصل واجهة الطالب عن واجهة المعلم.
4. فصل المحتوى المعتمد عن المحتوى المولّد.
5. التطوير يتم على مراحل صغيرة قابلة للفحص والتراجع.
6. لا انتقال إلى مصدر بيانات جديد قبل إثبات التكافؤ مع المصدر السابق.
7. لا AI حي قبل مرحلة التأليف المعتمدة.
8. لا ألعاب تعليمية بلا هدف تعلم واضح.
9. لا تجارب عملية بلا `safetyLevel`.
10. RTL والتصميم جزء من الأساس، لا مرحلة تجميل لاحقة.
11. لا اعتماد على وصف "تم التحديث"؛ إغلاق القرارات التوثيقية يحتاج تغييرات فعلية قابلة للفحص في Git.
12. لا تعديل migration مطبقة؛ التصحيحات تضاف في migrations جديدة.
13. لا مفاتيح Secret أو `service_role` في كود العميل الأمامي.
14. `npm run test` يجب أن يبقى مستقلاً عن Docker والشبكة؛ التكامل له أمر منفصل.
15. أي كتابة محمية لبيانات الطالب يجب أن تمر عبر عقد خدمة/Repository واضح وحاجز خادمي، لا من مكوّن React مباشرة.
16. لا يُنشأ وسم تجميد قبل نجاح أمر الإغلاق على الالتزام نفسه وتطابقه مع `origin/main`.

## قرارات المنتج والمعمارية

### التنقل

التنقل الحالي داخل تجربة الطالب يعتمد على `useState` وآلة حالات typed في `App.tsx`. لا يستخدم المشروع `react-router` حاليًا. يُعاد تقييم Router فقط عند الحاجة إلى روابط عميقة، مشاركة عناوين صفحات، أو سجل متصفح حقيقي.

### مصدر المحتوى

يصل التطبيق إلى المحتوى عبر `ContentRepository` فقط. اختيار `local` أو `supabase` يتم مركزيًا، ويظل `local` افتراضيًا حتى يُفعّل Supabase صراحة في البيئة المناسبة.

### Auth والصلاحيات

Supabase Auth هو مزوّد الهوية الرسمي، و`public.profiles` هو مصدر الدور وحالة الحساب. التفويض يمر عبر سياسة مركزية وحراس React، بينما تبقى GRANT وRLS حاجز الأمان النهائي. منظومة Auth مجمّدة عند `v0.4-auth-security-complete`.

### Cloud Persistence

حفظ نتائج الإتقان منفصل عن Seed المحتوى وعن Repository القراءة. يمر المسار عبر `MasteryResultsService` و`SupabaseMasteryResultsRepository` ثم RPC واحدة معتمدة، ويحفظ المحاولة والإجابات ذريًا مع idempotency ومصالحة النتيجة الرسمية. أي بيانات طالب سحابية جديدة خارج نتائج الإتقان تحتاج عقدًا مستقلًا ولا تُعتبر ضمن Phase 2-D تلقائيًا.

### لوحة المعلم والذكاء الاصطناعي

لوحة المعلم Phase 3. التأليف بمساعدة الذكاء الاصطناعي Phase 4، وكل ناتج AI يبقى `draft` حتى المراجعة البشرية والاعتماد.

## تعريف نقاط الاستقرار

```text
v0.3-data-layer-complete
→ اكتمال طبقة بيانات المحتوى

v0.4-auth-security-complete
→ اكتمال Auth والصلاحيات والإغلاق الأمني

v0.5-mastery-results-cloud-complete
→ يُنشأ بعد نجاح D5-C2 على الالتزام النهائي، ويوثق اكتمال حفظ نتائج الإتقان السحابي
```

لا يعني `v0.5` اكتمال لوحة المعلم أو التأليف بالذكاء الاصطناعي أو Production Readiness؛ تلك تبقى مراحل لاحقة مستقلة.

## معيار التوسع

عند إضافة صف أو مادة أو فصل جديد:

- تُحدّث ملفات المصدر المنظم أولًا.
- يُعاد توليد Seed آليًا.
- تُشغّل اختبارات الوحدة والتكافؤ وSupabase المحلية.
- لا يُقبل اختلاف صامت في الترتيب أو الحقول بين المزوّدين.
