# رفيق العلوم — خطة المراحل

## الحالة المعتمدة عند نقطة التجميد

نقطة التجميد الحالية تأتي بعد إغلاق طبقة البيانات السحابية كاملة حتى:

- Phase 2-A: طبقة الاستعلامات غير المتزامنة وترحيل واجهات الطالب.
- Phase 2-B1: عميل Supabase الكسول وإعداد البيئة.
- Phase 2-B2: Schema + RLS + Seed + التحقق المحلي القابل لإعادة التشغيل.
- Phase 2-B3: SupabaseContentRepository + اختبارات التكافؤ + اختيار المزوّد المركزي.

آخر نقطة استقرار معتمدة قبل إنشاء الوسم هي commit `fc1dfac`.

## قرارات ملزمة للخارطة

### Auth + الصلاحيات

لم تُلغَ ولم تُدمج ضمنيًا داخل طبقة المحتوى. موقعها الرسمي هو **Phase 2-C**، وتبدأ بعد نقطة التجميد الحالية. تشمل الهوية والجلسة والأدوار والصلاحيات، ولا تشمل لوحة المعلم كاملة.

### Cloud Persistence

لم تُلغَ ولم تُرحّل بصمت إلى مرحلة غير مسماة. موقعها الرسمي هو **Phase 2-D**، وتشمل في الحد الأدنى `mastery_results` وأي بيانات طالب تحتاج الاستمرار بين الجلسات والأجهزة. تعتمد على هوية Phase 2-C، لذلك تأتي بعدها.

### لوحة المعلم والذكاء الاصطناعي

تبقى لوحة المعلم في Phase 3، ويبقى التأليف بمساعدة الذكاء الاصطناعي في Phase 4. لا يُستخدم الذكاء الاصطناعي لتجاوز دورة المراجعة والاعتماد البشرية.

## نقطة التجميد

بعد اعتماد هذه الوثائق وإنشاء commit التجميد، يُنشأ الوسم:

```text
v0.3-data-layer-complete
```

يجب أن يشير الوسم إلى **commit التجميد التوثيقي الجديد** المبني فوق `fc1dfac`، لا إلى commit أقدم ولا إلى حالة محلية غير ملتزمة.

## قاعدة التغيير

أي تعديل لاحق على ترتيب المراحل أو نقل Auth أو Cloud Persistence يحتاج قرارًا مكتوبًا وتحديثًا مباشرًا لهذه الوثيقة في نفس الالتزام، لا وعدًا شفهيًا مؤجلًا.
