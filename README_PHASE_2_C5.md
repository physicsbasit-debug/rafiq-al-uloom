## القرارات الأساسية

- تحافظ C5 على قرار C2-B بعدم إعادة قراءة Profile عند:

```text
token_refreshed
user_updated
password_recovery
mfa_challenge_verified
unknown
```

- RLS تطبق تغير الدور أو الحالة إداريًا فورًا.
- تزامن الواجهة يتم عبر `refreshAuthorization()` الصريح، لا عبر طلب دوري عند كل تجديد Token.
- فرضية `retrySession()` تختبر كفجوة تهيئة أولى محتملة، ولا تستخدم لتغيير سياسة أحداث الجلسة المهيأة.
- أي إصلاح إنتاجي يحتاج اختبارًا فاشلًا أولًا.
- فشل Sign Out لا يحول التطبيق إلى Guest كذبًا.
- نتائج Profile المتأخرة لا يجوز أن تنتقل بين المستخدمين.
- C5 لا تكرر اختبارات C2 وC4، بل تختبر دورة الحياة والتركيب.

## التمييز الملزم

مسار Retry المحتمل يعالج جلسة مستعادة لم يصدر عنها Auth event بعد. أما `token_refreshed` و`user_updated` فيصدران عن جلسة مهيأة ومتزامنة بالفعل، ولذلك لا يعيدان قراءة Profile.
